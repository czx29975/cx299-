# 安语 · 居家养老语音助手（可用系统）

一套真的能用的居家养老系统，不是演示页：**老人端、家属端、社区端**三个界面，共用一个服务端和一份数据库，账号分角色、数据落库、告警真的会流转、对话可以接真实大模型。

- 老人说话或打字 → 助手听懂、执行（确认吃药、记血压、叫人），并回话
- 家属打开就看到告警、用药、血压、留言，可以发留言、代确认、撤回授权
- 社区端把求助变成工单：接单 → 到场 → 结案，超时自动升级，全程留痕

## 能做什么

| 场景 | 现在是怎么实现的 |
|------|------------------|
| 老人说"我吃过了" | 大模型听懂 → 服务端确认用药 → 家属端同步 |
| 老人说"打给女儿" | 直接显示「拨打 李梅」按钮，手机点一下就拨号（`tel:`），电脑上提示号码 |
| 老人量血压 | 手填或口述，写入趋势；老人端和家属端各有一张折线图 |
| 家属调整药 | 家属端「用药计划」可增删改，立刻影响之后的提醒，历史记录不变 |
| 老人说"我头疼" | 真的建一条症状记录 + 告警推给家属，助手说的"已经告诉李梅了"不是空话 |
| 老人说"胸口疼、喘不上气" | 模型自己升级为紧急求助，症状同时留档，事后能复盘老人原话 |
| 老人喊救命 | 开启「守护聆听」，听到就自动报警，不用碰手机；说「不舒服」会先问一句，20 秒没回应也报警 |
| 求助发出去没人知道 | 配好企业微信/钉钉机器人，SOS 直接推到家人手机；值守台同时响警报音；每位紧急联系人另外收到**短信** |
| 短信也不看怎么办 | 60 秒没人接单就开始**打电话**：第 1 顺位 → 第 2 顺位 → 社区值班 → 全员循环，直到有人接单 |
| 注册时用假号、虚拟号 | 短信验证码 + 号段白名单，`170/171/162/165/167` 与物联网卡一律注册不了 |
| 老人一直没动静 | 超过 6 小时没有任何交互（说话、确认药、量血压），白天自动提醒家属回电 |
| 出事按红按钮 | 3 秒倒计时可取消 → 建工单 → 60 秒无人接单自动升级 → 家属浏览器弹通知 |
| 社区没人守夜 | 打开社区端「AI 值守」，新工单自动接单、生成方案、留言通知，常规单直接闭环，SOS 自动升级 |
| 家属不在电脑前 | 打开「开启通知」，新告警会以系统通知弹出（手机需允许通知） |
| 手机上用 | 支持「添加到主屏幕」，全屏打开，像 App 一样有图标 |

## 一、启动

1. 确认本机有 **Python 3.10+**（命令行执行 `python --version` 能看到版本号）。
2. 双击根目录的 **`启动安语.cmd`**。
3. 浏览器会自动打开 <http://127.0.0.1:8080/>。
4. 第一次打开会进入**设置向导**，填老人信息、常用药、三个账号。填完用手机号登录。

关闭那个黑色窗口即停止服务；服务只在开机并启动后才对外提供访问。

### 三个账号

设置向导会创建三个账号，角色不同、看到的界面不同：

| 账号 | 登录后 | 能做什么 |
|------|--------|----------|
| 老人 | 老人端 | 语音/文字对话、点「吃了」确认用药、记血压、按求助、听留言 |
| 家属 | 家属端 | 看告警与周报、代确认用药、留言、交接健康数据授权、改密码 |
| 社区 | 社区端 | 工单接单/到场/结案、辖区名册、指标、账号管理、大模型设置 |

密码用 PBKDF2（18 万次迭代）加盐存储，登录后发 HttpOnly 会话 Cookie，服务端逐接口校验角色。

## 一之二、注册与登录（短信验证，挡住虚拟号码）

登录页 <http://127.0.0.1:8080/login.html> 有两个方式：**密码登录**和**短信验证码登录**；右上角可以进 **注册**、**忘记密码**。

### 为什么必须短信验证

家属手机号是出事时唯一能叫醒人的通道。接码平台的虚拟号、物联网卡、卫星号能收短信，但经常打不通、没人接、也回拨不了。所以注册这一关就把它们拦住：

| 拦截对象 | 号段 |
|---|---|
| 虚拟运营商（移动转售） | `162` `165` `167` `170` `171` |
| 物联网 / 上网卡 | `140`–`144` `146` `148` |
| 卫星通信 | `174` |
| 座机 / 400 / 95xx / 长度不对 | 直接拒 |
| 明显假号 | 尾号全同（`13800000000`）、`12345678` 之类顺子 |

校验用**号段白名单**：只放行移动 `134-139/147/150-152/157-159/172/178/182-184/187/188/195/197/198`、联通 `130-132/145/155/156/166/175/176/185/186/196`、电信 `133/149/153/173/177/180/181/189/190/191/193/199`、广电 `192`。白名单之外一律不放，新号段上线时在 `app/sms.py` 顶部加一行即可。

> 想再严一层：社区端 →「短信」里勾上**号码百科在网核验**，注册时会调阿里云判断是否停机/空号。第三方接口失败不会挡住注册（宁可放过，也不能因为接口抽风把人拦在门外）。

### 防短信轰炸

发码接口在公网上就是一台短信轰炸机，所以加了三道闸：

1. **先过图形验证码**（4 位字符，3 分钟有效，一次性）；
2. **频控**：同一手机号 60 秒 1 条、24 小时 10 条；同一 IP 每小时 12 条、每天 40 条；
3. **验证码只存哈希**，5 分钟过期、一次性、错 5 次作废。

密码登录也做了节流：同一 IP + 同一手机号 10 分钟内错 8 次，锁 10 分钟，并提示改用验证码登录。

### 接入真实短信网关

没接网关时，是**本地自测模式**：验证码打印在服务端窗口，同时直接显示在页面上，功能能完整跑通但不会真发短信。

正式接：社区端右上角 **「短信」**，选服务商填配置：

| 服务商 | 需要的字段 |
|---|---|
| 阿里云短信 | AccessKeyId / Secret、签名、验证码模板 CODE；告警短信模板可选 |
| 腾讯云短信 | SecretId / Key、SdkAppId、签名、模板 ID |
| 自定义网关 | 一个 URL，收到 `POST {phone, scene, code, text}` |

模板变量：验证码模板用 `${code}`；告警模板用 `${elder}`（老人称呼）和 `${reason}`（求助原因）。填完点「发测试短信」，成功失败都会显示服务端原文，最近 12 条下发记录在同一个弹窗里可查。

### 注册时绑哪位老人

陌生人不能随便认领别人的老人，所以只有两条路：

- **用绑定码**：社区端 →「成员」→ 家属绑定码 → 生成 6 位码（默认 72 小时、一次性）。家属注册时填码即绑定。
- **新建档案**：家里还没建档时，注册时直接填老人姓名/年龄/住址/社区，系统建一份 `pending` 档案，家属即监护人。

注册成功后自动登录，并把家属手机号写进**紧急联系人**名单——这是外呼能打通的前提。

## 二、接上真实大模型（建议第一件事）

没有配置大模型时，对话走**内置指令引擎**（能识别"我吃过了""血压 135 85""打给女儿""今天几号""我有点孤单"等），功能真实但听不懂自由表达。

### 用 DeepSeek（推荐）

1. 打开 <https://platform.deepseek.com> 注册，进入 **API keys** 创建 Key（形如 `sk-...`），复制；
2. 用社区账号登录 → 右上角 **「大模型」**；
3. 服务商选 **DeepSeek（推荐）**，地址与模型会自动填好（`https://api.deepseek.com/v1` + `deepseek-chat`）；
4. 粘贴 Key → 点 **「测试」**。成功会显示类似 `调用成功：deepseek-chat · 860 ms · 回话「我在」`；
5. 点 **「保存」**，老人端对话立刻走大模型。

Key 只写进本机数据库，前端只显示 `sk-abc...7890` 这样的掩码；换 Key 直接在同一个面板粘贴新的，**清除**按钮可退回内置指令。

### 不想登录网页？用命令行接

双击根目录 **`接入大模型.cmd`**，按提示选服务商、粘贴 Key，脚本会**当场做一次真实调用**并打印结果：

```
已保存：deepseek-chat · https://api.deepseek.com/v1 · sk-abc...7890
正在用真实对话测试…
  接入成功  ✓   用时 860 ms
  模型回话：我在呢，您有什么事慢慢说。
```

失败也会直接说人话，例如 `Key 不正确或已失效，请到 DeepSeek 控制台重新生成`。写库后**立即生效，不用重启服务**。

也可以直接传参数：

```bash
cd app
python set_llm.py --status                       # 看当前配置
python set_llm.py --provider zhipu --key sk-xxx  # 智谱免费额度
python set_llm.py --clear                        # 退回内置指令
```

### 换别家

面板里内置了通义千问、智谱 GLM、OpenAI 的预设，选完会自动填地址与模型，粘 Key 即可。自定义接口就选「自定义」，自己填地址和模型名。

| 服务 | 接口地址 | 模型名 |
|------|----------|--------|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 智谱（有免费额度） | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 本机 Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |

**只想先试试、不想付费**：智谱的 `glm-4-flash` 注册后有免费额度，够日常试用；把上面「智谱」一行的地址和模型名填进去即可。

也可以用环境变量 `ANYU_LLM_KEY`（优先级：环境变量 > 界面设置 > `config.json`）。

> 模型名建议用 `deepseek-chat`。`deepseek-reasoner`（R1）思考链更长、回话慢，且不一定支持 JSON 模式——程序会自动去掉该参数重试一次，但老人等待时间会明显变长。

### 接上之后会怎样

老人说"我今天吃药了没""我闺女叫什么""我有点闷"，助手会结合用药、血压、家属信息回答，并自行决定是否调用记录血压、确认用药、发起求助等动作。**所有写库动作都由服务端执行并校验，不交给模型直接改数据。**

### 出错了怎么查

面板会直接显示上次失败的原因，比如：

- `Key 不正确或已失效` → 去控制台重新生成
- `账户余额不足` → 先充值
- `模型名或接口地址不对` → 确认地址以 `/v1` 结尾、模型名拼写正确
- `连不上模型服务` → 电脑网络或代理问题

无论哪种失败，老人端都不会卡住：会自动退回内置指令，并在对话标签上标注"已切到内置指令"。

## 三、手机上用

手机浏览器只有在 **HTTPS** 下才允许开麦克风，所以本项目同时开了两个端口：

- `http://<电脑IP>:8080/` —— 电脑上用
- `https://<电脑IP>:8443/` —— 手机用（自签名证书）

启动窗口会打印局域网地址，例如：

```
局域网：http://10.159.14.116:8080/
手机：  https://10.159.14.116:8443/
```

手机上第一次打开会提示"证书不安全"，点 **高级 → 继续访问** 即可（自签名证书没有机构背书，属于正常现象；局域网内流量仍被加密）。

**添加到主屏幕**（推荐，老人用起来更省事）：Safari 点底部分享 → 添加到主屏幕；Chrome / Edge 点右上角菜单 → 添加到主屏幕。加完之后桌面有"安语"图标，打开是全屏的，没有地址栏，跟 App 一样。断网时也能打开登录页。

换了 WiFi 导致 IP 变化、或证书过期时，在 `app/` 目录执行一次：

```bash
python make_cert.py
```

会按当前 IP 重新生成证书，重启服务生效。

> 如果手机打不开，多半是 Windows 防火墙拦了。第一次启动时允许"专用网络"访问即可，或在防火墙里放行 8080 / 8443 端口。

### 外网访问

默认只监听局域网。要让不在同一网络的家人使用，需要：

1. 有公网 IP：路由器上把 8443 端口映射到这台电脑；
2. 没有公网 IP：用 frp / cloudflared / ngrok 之类的内网穿透，把本地 8443 暴露成 HTTPS 域名（推荐，省去证书麻烦）；
3. 正式对外前，请换掉自签名证书、把 `config.json` 里的 `host` 按需调整，并改掉初始密码。

## 三之二、紧急求助：发现 → 通知 → 打电话

原来的求助只有一条路：老人自己按下红按钮。老人摔倒在地、说不出话、或者手机不在手边，这条路就断了。这一版补了三层。

### 第一层：怎么发现

| 方式 | 说明 |
|---|---|
| **守护聆听**（老人端顶栏开关） | 页面持续听着，听到「救命」「摔倒了」「起不来」「胸口疼」「喘不上气」等，**5 秒倒计时后自动求助**，不用碰手机 |
| 模糊不适的二次确认 | 听到「不舒服」「头晕」「心慌」等先问一句"要我叫人吗"，**20 秒没回应就直接报警** |
| 红按钮 | 原有方式，保留 |
| **设备失联检测** | 老人端每分钟上报心跳；超过 **10 分钟**没动静（断网、关机、被拔电）自动建单提醒家属 |

守护聆听默认关闭，打开后会记住设置，下次进页面自动恢复。顶部会显示"守护中"的呼吸灯，避免老人不知情。

> 注意：守护聆听依赖浏览器的语音识别，需要联网、需要麦克风权限。**它不是硬件跌倒检测**——真要做无感跌倒检测，得配雷达或可穿戴设备。

### 第二层：通知到人

社区端右上角 **「通知」**，填一个地址就能用，全部免费：

| 通道 | 怎么拿 |
|---|---|
| 企业微信群机器人 | 建一个只有家人的群 → 群设置 → 群机器人 → 添加 → 复制 Webhook |
| 钉钉群机器人 | 群设置 → 智能群助手 → 添加机器人 |
| Server酱 / PushPlus | 关注公众号拿 SendKey / token，消息推到微信 |
| 自定义 Webhook | 接你自己的短信网关，会收到 `{title, text, level, elder, alert_id}` |

紧急求助触发时，**所有已配置通道同时发**，内容是：老人称呼、年龄、住址、基础病、过敏、发生了什么、时间。发完写 `notify_logs`，成功失败都能查。

点「发一条测试」可以立刻验证通道通不通。

### 第三层：逐级外呼（电话真的会响）

只有**短信 + 群消息**还不够：群里没人看，短信静音了也不看。所以求助后会按时间往上叫人，直到有人点「接单」。

**第 0 秒**：给每位紧急联系人发短信（不是群消息，是发给本人），同时推到已配置的群机器人。

之后进入阶梯，只在工单还是「待接单」时推进——有人接单就立刻停，避免骚扰：

| 时间 | 做什么 |
|---|---|
| 60 秒 | 电话拨给**第 1 顺位**家属（播 1 遍） |
| 3 分钟 | 加呼**第 2 顺位** |
| 5 分钟 | 加呼**第 3 顺位** + 社区值班电话 |
| 10 分钟 | 转为**全员循环外呼**，每 5 分钟一轮，直到有人接单 |

每次拨号都写 `call_logs`（第几级、打给谁、成功还是失败、服务端原文），并写进工单时间线；社区端工单详情里能直接看到"已升到第几级、打了谁"。

**维护名单**：家属端 →「紧急联系人」，可以加人、改顺位、删人。顺位越小越先打。没填手机号的家属账号会被自动跳过（虚拟号段加不进来）。

> 电话外呼需要**阿里云语音通知**（企业实名 + TTS 模板审核，见社区端「通知」）。只配了短信也能用：短信会到达，只是没有电话。**系统不会自己拨 110/120**，这需要专线资质与合作。

### 社区端的声音报警

值守台收到求助时：顶部红色横幅 + **持续警报音 + 语音播报**（"紧急求助，王秀兰，摔倒在地"），浏览器标签标题也会一闪一闪。值守员在菜市场都能听出来出事了。

**怎么保证真的会响**（浏览器默认禁止网页自动出声，这是最常见的"没声音"原因）：

| 情况 | 界面上的表现 |
|---|---|
| 浏览器还没放行声音 | 顶栏按钮显示红色「开启警报」，横幅里也有「开启声音」按钮，点一下就解锁 |
| 已放行 | 顶栏变绿色「警报已开」，横幅只剩「去处理 / 静音」 |
| 有人点了页面任意位置 | 自动解锁，不需要专门找按钮 |

**什么时候停**：

- 点「静音」→ 铃声停，横幅留着；**再来新的求助会重新响**（不会因为手滑静音就漏掉下一条）；
- 真人点「接单」或「结案」→ 自动停；
- **AI 值守接单不算有人管**：AI 接单后铃声继续响，横幅注明"AI 已接单，仍等真人确认"——否则 AI 秒接单，值守员根本不知道出过事；
- 一直没人处理时，最多连响 **10 分钟**后自动静音（横幅仍在），避免半夜折磨人；来新求助会重新响。

**可调项**（顶栏「警报」按钮）：声音报警开关、语音播报开关、是否一直响到有人处理（关掉则只响 30 秒）、音量。

> 铃声用 Web Audio 合成后**循环播放**，不依赖定时器——标签页切到后台被浏览器降频时也不会断断续续。但**关掉这个页面就听不到了**，值守机请把页面常开（可以「添加到主屏幕」当 App 用）。

## 四、自动发生的事（后台任务）

服务内置一个每 15 秒扫描一次的后台线程，和人工操作写同一张告警表：

- **用药超时**：到点 90 分钟仍未确认 → 自动建一条 `warn` 工单，通知家属与社区；
- **求助升级**：SOS 60/180/300/600 秒按阶梯逐级外呼，无人接单就一直往上叫人；3 分钟未到场 → 追加"建议立即转 120"；
- **设备失联**：开启守护的终端超过 10 分钟没上报心跳 → 建单提醒（`HB_FROM/HB_TO` 只在 7:00–23:00 检查）；
- **静默守护**：老人超过 6 小时没有任何交互（说话、确认用药、量血压、报症状），**白天 10:00–21:00** 自动建一条「长时间没有动静」提醒家属回电，每人每天最多一次；
- **会话清理**：过期登录态自动删除。

这些都可在社区端「工单详情 → 事件时间线」里看到是谁、在几点、做了什么。

阈值都在 `app/jobs.py` 顶部，想改直接改常量再重启：

| 常量 | 默认 | 含义 |
|------|------|------|
| `MED_LATE_MIN` | 90 分钟 | 用药过点多久算"没吃" |
| `SOS_ESCALATE_1` | 60 秒 | 无人接单多久开始升级 |
| `SOS_ESCALATE_2` | 180 秒 | 多久追加"建议转 120" |
| `ESCALATION_LADDER` | 60/180/300/600 秒 | 逐级外呼的阶梯（在 `service.py`） |
| `CALL_REPEAT_SEC` | 300 秒 | 第 4 级之后的循环间隔 |
| `RESEND_GAP` / `PHONE_DAY_LIMIT` / `IP_HOUR_LIMIT` | 60 秒 / 10 条 / 12 条 | 短信频控（在 `sms.py`） |
| `INACTIVE_HOURS` | 6 小时 | 多久没交互算"没动静" |
| `INACTIVE_FROM` / `INACTIVE_TO` | 10 / 21 | 只在白天这个区间内检查，避免半夜误报 |
| `HEARTBEAT_GAP_MIN` | 10 分钟 | 多久没心跳算设备失联 |

## 四之二、AI 值守（社区端）

社区端右上角 **「AI 值守」** 打开后，新工单会被自动接管：**接单 → 生成处置方案 → 给老人和家属留言 → 结案或升级**，每一步都写进事件时间线，责任人是「AI 值守」。

开启后社区端按钮旁会出现一个小绿点，弹窗里能看到最近处置记录。

### 执行流程

1. 后台每 5 秒扫描一次待接单工单，只接管存在超过 3 秒的单（给真人留反应时间）；
2. 把工单 + 老人档案（年龄、基础病、过敏、今日用药、最近血压、最后活动）交给大模型；
3. 模型只输出方案 JSON，**不能改数据库**；接单、留言、升级、结案全部由服务端执行；
4. 每次处置写一条 `duty_runs`，可在面板里回看。

### 安全边界（写在代码里，不由模型决定）

| 工单类型 | 自动接单 | 自动结案 |
|---|---|---|
| 紧急求助 `sos` | 是，并立即升级通知社区与家属 | **否**，必须真人确认安全 |
| 用药未确认 `med` | 是 | 是（提醒已补发、家属已通知） |
| 长时间没动静 `inactive` | 是 | **否**，需家属回电确认 |
| 身体不适 `symptom` | 是 | 由模型判断，须写明结案依据 |

另外：

- 模型被明确禁止编造电话号码、门牌号、亲属信息——需要联系方式时只能写"请联系家属"；
- 自动结错的单，在工单详情里有 **「重新打开」**，会写进时间线；
- 没接大模型时自动降级为**规则值守**，行为一致但方案是固定模板，记录里标注 `rule`。

### 关掉它

同一个弹窗把开关关掉即可，立刻恢复人工值守；已经处置过的记录保留。

## 五、数据与备份

- 数据库：`app/data/anyu.db`（SQLite 单文件，含 WAL 日志）。
- **备份**：停掉服务，把 `anyu.db`（连同 `-wal`、`-shm`）复制走即可。
- **迁移**：把整个 `app/` 目录拷到新机器，装好 Python 就能跑。
- **重置**：停掉服务，删掉 `app/data/` 目录，重新启动会回到设置向导。

数据都在本机，不上传任何第三方；只有配置了大模型后，"对老人说的话 + 当前用药/血压摘要"会发给你选定的模型服务商。这属于必要的最小上下文，可在家属端随时撤回健康数据授权。

## 七、常见问题

**麦克风点不动 / 提示不允许**
浏览器只允许在 `https://` 或 `127.0.0.1` 下使用麦克风。手机请用 `https://IP:8443`，并允许麦克风权限。

**助手只会那几句固定回答**
说明还没接大模型，或 Key 失效。社区端 →「大模型」→ 点测试看具体报错。

**提示端口被占用**
改 `app/config.json` 里的 `server.http_port` / `https_port`，重启服务。

**家人手机能打开页面但登录不了**
确认用的是同一个手机号；忘记密码可以点登录页「忘记密码」用短信重置，或让社区账号在「成员」里点"重置密码"。

**注册时提示"虚拟运营商号码"**
这是故意的。`170/171/162/165/167` 是移动转售号段，出事时经常无人接听。请换成移动/联通/电信/广电的实名手机号。如果确实只有这一类号码，可以让社区账号在「成员」里直接建账号（不受号段限制，但也不建议）。

**短信一直收不到**
先看社区端「短信」里的状态：显示"未接入"说明还在本地自测模式。接入后点「发测试短信」，服务端原文会显示出来（常见原因：签名未审核、模板变量对不上、余额不足）。

**删了数据想重来**
停服务 → 删 `app/data/` → 重启。

## 八、边界（请务必知道）

1. 这不是医疗器械：不诊断、不开药、不调剂量，不替代 120、子女、护工与社区。
2. 求助会通知系统里的家人和社区。**电话外呼（含逐级外呼）需要你自备阿里云语音通知账号**（企业实名 + 模板审核），短信需要阿里云/腾讯云短信账号；系统不会自己"报警"，直接拨 110/120 需要专线资质与合作，任何软件都做不到。
3. 前端的语音识别与朗读用的是浏览器能力，识别质量取决于设备和网络；助手说话的语速可在设置里放慢。
4. 自签名证书会触发浏览器警告，正式对外使用请换成正规证书。
5. **AI 值守不能替代真人**：它只会接单、留言、通知、归档，不会上门，也不会判断老人是否安全（配了阿里云外呼时会拨号，但只是念固定模板，不等于确认了现场）。
   紧急求助永远停在「处理中」，等人确认；正式使用前请先定清楚谁负责兜底。
6. 医疗、急救、支付与个人信息处理相关功能上线前，需按当地法规完成专项合规评审。
